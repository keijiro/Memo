# Slidev

https://sli.dev

Web 技術をベースとしたプレゼンテーションシステム。Web ブラウザ上でスライドデッキを再生できる。

## 良い点

### コーディングエージェントとの親和性の高さ

スライドは基本的に Markdown で記述するため、コーディングエージェントによる編集が非常に容易である。また、エージェントにとって扱い慣れた Web 技術がベースとなっているため、柔軟なカスタマイズにも対応できる。公式 Skill も提供されており、Slidev 固有の作業も問題なく任せられる。

### プレゼンテーションシステムとしての出来の良さ

スピーカー画面とプレゼンテーション画面の同期、アノテーションの書き込みなど、基本的な機能が一通りそろっている。さらに、スピーカー画面上のマウスポインターをプレゼンテーション画面にも反映する機能など、ほかのプレゼンテーションシステムではあまり見られない便利な仕組みも備えている。

### その他の長所

- Git でのバージョン管理が容易。
- コーディングエージェントを活用すれば、翻訳を容易に行える。
- テーマの複製や模倣がしやすく、これらの作業もエージェントに任せられる。
- GIF やトランスコード済みの動画に限らず、自分でエンコードした動画を使用できる。
- 静的 Web サイトとして、GitHub Pages などで共有できる。
  - 機材に不具合が発生した際の最終手段としても有効。Web ブラウザを利用できる環境さえあれば、プレゼンテーションを続行できる。
- .pptx や .pdf など多彩な形式に出力できる。
  - .pptx の場合はスピーカーノート付きにできる。
  - ただし動画の埋め込みはできない。

## 注意点

### 自動再生（autoplay）の制約

動画を自動再生するには、そのブラウザインスタンス上で、少なくとも一度はユーザー操作を行っておく必要がある。マウスを一度クリックするだけでもよい。

一見すると大した制約ではないが、スピーカー画面を使って発表する場合、プレゼンテーション画面を一度も操作しないままフルスクリーン表示にしてしまう可能性がある。そのため、プレゼンテーション画面を意識して「一度クリック」しておく必要がある。

この制約によるトラブルを防ぐため、プレゼンテーションの最初のページには「こちらの画面を一度クリックすること」という注意書きを入れるようにした。

### 動画の `print-timestamp`

仕様上は、動画要素に `print-timestamp` を設定することで、印刷時やプレビュー時に置換画像として使用するフレームを指定できる。しかし、実際に試したところ、この機能は正常に動作しなかった。

そのため、最終的にはすべての動画に `print-poster` を設定することになった。この作業もコーディングエージェントに任せられるため、それほど大きな負担ではない。
